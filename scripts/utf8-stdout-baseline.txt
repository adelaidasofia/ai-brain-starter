# utf8-stdout-baseline.txt - the legacy population under
# scripts/check-utf8-stdout.py, pinned by SHA-256 of NEWLINE-NORMALIZED content.
#
# THIS FILE IS A BACKLOG, NOT A SET OF PARDONS.
#
# Every row is a runnable file that writes to the console, can emit non-ASCII,
# and carries no UTF-8 reconfigure guard - the ai-brain-starter#313 cp1252 crash
# class. They predate the guard's SCOPE, not its predicate: until MYC-3530 this
# lint only ever scanned scripts/*.py, so hooks/ was never looked at. All 78
# rows pinned at the start were files the ORIGINAL, unwidened predicate would
# already have flagged. Pinning them lets the CLASS-level guard cover hooks/
# without a 78-file rewrite, while still failing the build for anything new.
#
# BURN-DOWN LOG. 78 rows were pinned at MYC-3530. For how many REMAIN, run
# `python3 scripts/check-utf8-stdout.py` -- it prints the live count and the
# per-tag split. Deliberately not restated here as a number: two rows came off
# in PRs that merged 22 minutes apart (#420, then #416), and the second one's
# hand-written "77 remain" was already wrong by the time it landed. A ledger
# that has to be hand-decremented is a ledger that lies.
#   - hooks/auto-capture-public-ships.py   guarded + unpinned in PR #420.
#   - hooks/vault-command-nudges.py        guarded + unpinned in PR #416. It was
#     edited there (the rm -rf rule now quotes the RESOLVED target back to the
#     user, so an emoji vault folder reaches stderr from the filesystem), which
#     staled its row and forced the choice this file already documents below:
#     guard it and delete the row, never re-pin. Deleted, per that rule.
#   - every SEV-1-hard-crash and SEV-2-ascii-pipe row  guarded + unpinned for
#     ai-brain-starter#314. Those two tags are the population where the guard is
#     unambiguously the right remedy: each does a RAW console write (not through
#     json.dumps) of a live literal the target codec cannot encode, so the crash
#     is reachable on a real console today. The negative control is
#     check-sync-folder-machinery.py, which printed its "MACHINERY FOUND IN
#     CLOUD-SYNCED FOLDERS" banner and died exit=1 with `UnicodeEncodeError:
#     'charmap' codec can't encode characters in position 13-14` under
#     PYTHONIOENCODING=cp1252, and exits 0 with the guard.
#     SEV-3-doc-only and SEV-4-json-encoded were deliberately NOT swept: this
#     file already rules that bulk-guarding SEV-4 "is the bulk grep-driven edit
#     MYC-3520 forbids" and that SEV-3 wants a per-file read (several want
#     `# utf8-stdout-ok: <reason>`, not the guard). They remain pinned, and come
#     off only per file, with a reviewer, as those rules require.
#
# THE RATCHET (same mechanism as scripts/vault-root-read-baseline.txt #407 and
# scripts/cloud-safe-walker-baseline.txt #411)
#   - A pinned file passes ONLY while its content still hashes to its row. Edit
#     it at all and the row goes STALE and the build fails, so the next person to
#     touch any of these files has to add the guard.
#   - A file NOT in this list has no grace period: it fails on the first run.
#   - Rows only ever get DELETED. Do not re-pin an edited file to keep it quiet
#     -- that converts the backlog into a permanent exemption, which is exactly
#     the failure mode this file exists to avoid. If the console output is
#     provably ASCII-only, it gets `# utf8-stdout-ok: <reason>` in the source
#     (where a reviewer sees it) and its row is deleted from here.
#
# WHY NEWLINE-NORMALIZED: this repo has no .gitattributes, so a Windows clone
# with core.autocrlf=true has CRLF on disk while the Linux CI runner has LF.
# Hashing raw bytes pins the CHECKOUT, not the CONTENT, and reports every row
# stale on the other platform. That regression was live and shipped as #411.
#
# ROW FORMAT
#   <sha256>  <TAG>  <path>
#
# TAGS - mechanically derived, worst first. They set the BURN-DOWN ORDER; they
# are not severity opinions. Derivation is reproducible from the source AST:
#
#   SEV-1-hard-crash    a console write that does NOT go through json.dumps, and
#                       a live (non-docstring) string literal containing a
#                       character cp1252 cannot encode. This crashes on a Windows
#                       console TODAY, on that code path. Fix these first.
#                       Literals actually found: U+2699 gear, U+2192 arrow,
#                       U+26A0 warning, U+2717 ballot-X, U+1F534 red-circle.
#   SEV-2-ascii-pipe    same raw console write, but every live literal IS
#                       cp1252-encodable (em dash, curly quotes, accents). It
#                       survives a Windows console and dies on a genuinely ASCII
#                       console or a C-locale pipe - the second half of the class
#                       this lint names in its own header.
#   SEV-3-doc-only      raw console write, but the non-ASCII appears ONLY in
#                       docstrings/comments. No literal is known to reach stdout;
#                       a runtime value still can. Read before fixing - several
#                       of these want `# utf8-stdout-ok: <reason>`, not the guard.
#   SEV-4-json-encoded  EVERY console write goes through json.dumps() with the
#                       default ensure_ascii=True, which escapes non-ASCII to
#                       backslash-uXXXX before it reaches the stream. Verified on
#                       a cp1252 console: json.dumps of a gear-prefixed string
#                       prints escaped and exits 0, while the same string printed
#                       raw raises UnicodeEncodeError. These are safe VIA THAT
#                       PATH and are pinned rather than "fixed": adding the guard
#                       to them is the bulk grep-driven edit MYC-3520 forbids.
#                       They come off the list only when a reviewer confirms
#                       per file.
#
# Counts at the time of pinning (MYC-3530): 21 SEV-1, 9 SEV-2, 6 SEV-3,
# 42 SEV-4, 78 total. Every row is under hooks/ - scripts/ is already clean.
